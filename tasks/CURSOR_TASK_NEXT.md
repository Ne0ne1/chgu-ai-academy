Функциональные требования
A. Runtime
- Pyodide только в выделенном Web Worker. В UI: loading/ready/running/error/unavailable, повтор загрузки после ошибки. Запуск без проверки не создаёт успешный Attempt.
- Ограничение времени одного запуска 5 секунд: остановка через terminate(), новый Worker после остановки. Ограничение вывода 20 KB и понятное уведомление об обрезке. Свежий namespace для каждой проверки, никакой утечки переменных из предыдущих запусков.
- Отмена при уходе со страницы; requestId для отбрасывания запоздалых ответов; нельзя повторно нажать запуск/проверку, пока запрос выполняется. Ошибки загрузки, Python, Worker, таймаут и несовпадение ответа различаются.
- Показать реальный stdout/stderr. Не выводить «успешно» при исключении. Тесты в клиенте открыты; это учебный браузерный прототип, не production-песочница для недоверенного серверного кода.

B. Проверка и методика
- «Проверить» запускает фактические тесты и создаёт Attempt с testResults, passed и timestamp. Не добавляй timeSpentSeconds без измерения.
- Для study-plan проверь значения и типы days/hours_per_day/total_hours, вычисленный результат и stdout. Проверка только print("За неделю: 15 ч") недостаточна. Сделай минимум два набора входных значений с явно согласованным контрактом; не меняй код ученика строковыми заменами. Используй две строки stdin для числа дней и часов; input() и int() уже объяснены в уроке. Явно обнови условие и starterCode под этот ввод. Не требуй ещё не изученных пользовательских функций. Проверки должны оценивать исполненное состояние Python, а не точное написание решения.
- Добавь задачу переноса: получить целое число из строкового исходного значения и вычислить другое значение с форматированным выводом; хотя бы два случая. Это не копия первой задачи с другим названием. Условие и подсказки не содержат готового решения. Сохрани их отдельно от JSX.
- После ошибки покажи ожидаемое/полученное, короткую причину и релевантную ссылку #names/#types/#conversion/#mistakes в уроке. Подсказки детерминированные, без заявления о работающем AI. Не раскрывай решение первой подсказкой.
- Отмечай mastered только для навыков, реально подтверждённых тестами. Не засчитывай все цели урока по единственному stdout. В evidenceAttemptIds должны быть существующие успешные попытки. Чтение, ответ в self-check, просмотр подсказки и нажатие «Запустить» mastery не повышают.
- После первой принятой задачи — один переход к задаче переноса. После обеих — ссылка к программе; не предлагай недоступный следующий урок.

C. Продолжение и прогресс
- Версионированное локальное хранилище chgu-ai-academy:learning:v1. Содержит lastLocation (lessonId, допустимый sectionId или exerciseKey), черновики, ограниченный журнал Attempt, Mastery; сохранять только нужные поля. Не использовать localStorage.clear().
- Валидация при чтении: версия, поля, ID из fixtures, ссылки на Attempt, разумные размеры. Повреждённый JSON, quota exceeded и запрет хранения не ломают обучение: явное сообщение «результат не сохранён» и рабочая сессия в памяти. Без window/localStorage на сервере и без hydration mismatch.
- Главная: до старта «Начать обучение»; после реального посещения/редактирования «Продолжить обучение» ведёт к допустимому сохранённому месту. Не навигировать к произвольному URL из storage.
- Программа: статусы «Не начато», «Изучается», «Нужно повторить», «Освоено» строго по событиям. Будущие темы не входят в знаменатель освоения доступных задач. Не превращай чтение секций в процент знаний.
- Прогресс: фактические принятые задачи, подтверждённые навыки, темы для повторения и один следующий шаг. Повторная проверка той же задачи не увеличивает количество выполненных задач. Ошибка при повторении не удаляет историю доказательств, но может ставить needs_review по явно описанному правилу.
- Сброс учебных данных — подтверждённое действие только для своего ключа. Сохрани выбор темы и чужие ключи. SSR и смена темы остаются рабочими.

Критерии готовности и тесты
1. Маршрут главная → урок → задача → ошибка → подсказка → исправление → проверка → задача переноса → прогресс пройден в браузере. Неверное решение не засчитывается.
2. Проверены правильный код, неверный вывод, печать константы вместо расчёта, неверный тип, SyntaxError, NameError, бесконечный цикл, большой вывод, сбой загрузки runtime, отмена и запоздалый ответ.
3. Перезагрузка восстанавливает черновик, попытки и «Продолжить». Повреждённый JSON/неизвестный ID/запрет localStorage не вызывают падение.
4. Тесты mastery, evidence, повторной попытки, отсутствия прогресса от чтения и простого запуска, сброса только своего ключа.
5. Нельзя засчитать устаревший результат после изменения кода. Показанный результат привязан к проверенному снимку кода.
6. Светлая/тёмная темы, 390px и десктоп, клавиатура, реальный Monaco и простой редактор. Никаких ошибок hydration; не писать E2E на mocked runtime как единственное доказательство работы Python.
7. npm ci; npm run build; npm run typecheck; добавь и выполни npm run test:learning и npm run test:e2e. Не объявляй проверки успешными, если окружение их заблокировало.
