Полное название: CHGU AI Academy — прототип адаптивного учебного цикла по основам Python. Краткое название: CHGU AI Academy.

Роли на текущем этапе: постановка учебного цикла, реализация интерфейса и Python-рантайма в браузере, проверка заданий, локальное сохранение прогресса, подготовленные подсказки наставника.

3. Аннотация проекта

CHGU AI Academy создаёт проверяемый учебный цикл «урок → задача → объективная проверка → помощь после ошибки → прогресс». Без регистрации доступны урок «Переменные и типы данных», две задачи с запуском Python в браузере (Pyodide), сохранение Attempt/Mastery локально и помощь в режиме подготовленных подсказок. Проект адресован студентам начального уровня. Статус: работающий прототип одного модуля, а не завершённая годовая программа.

4. Проблема и актуальность

Проблема: при самостоятельном изучении программирования студент часто не получает быстрой объективной обратной связи. Чтение теории и самопроверка не подтверждают навык; без запуска кода ошибка остаётся неочевидной; готовые ответы чат-ботов легко выдают решение целиком.

С кем встречается: студенты нулевого/начального уровня; преподаватели вводных курсов, которым нужен прозрачный учебный контур до тяжёлой инфраструктуры LMS.

Актуальность подтверждается практикой вводных курсов программирования (ориентиры открытых программ вроде CS50 Python), где цикл «объяснение → задача → проверка» является базовым. Официальное партнёрство с Harvard/MIT/fast.ai/Hugging Face не заявляется.

5. Целевая аудитория и сценарии

Студент-новичок: проходит урок, сдаёт задачу, видит ошибку тестов, читает подсказку, исправляет, сохраняет прогресс.

Гость демо / судья: без регистрации проходит путь главная → урок → неверная попытка → подсказка → успешная проверка → прогресс.

Методист пилота: проверяет, что оценка ставится только тестами, а помощь не меняет Mastery.

6. Цель и задачи

Цель: показать реализуемый прототип адаптивного обучения программированию с объективной проверкой кода в браузере и честной маркировкой режимов помощи.

Реализовать урок и две проверяемые задачи по переменным.

Подключить Pyodide в Worker с ограничениями времени и вывода.

Сохранять Attempt/Mastery локально с валидацией доказательств.

Дать помощь после ошибки без готового решения первой репликой.

Подготовить пилотный контур внедрения на небольшой группе студентов.

7. Решение и новизна

Как работает: Next.js + практика с Monaco/простым редактором; выполнение Python только в браузерном Worker; grading по stdout и состоянию переменных; наставник в публичном демо — подготовленные подсказки с явной маркировкой. Опциональная локальная Ollama технически предусмотрена для частного сервера, в публичном демо не используется и живьём не проверялась.

Сравнение с альтернативами по конкретным функциям (без заявления «уникальности»):

Moodle / типовая LMS: сильна в курсах и оценках преподавателя; обычно нет встроенного браузерного Python-рантайма «из коробки» и узкого цикла mastery только по тестам кода.

Видео/лектории (класс Coursera-подобных курсов): дают контент и квизы; слабо закрывают локальный запуск кода студента и адресный разбор конкретной ошибки исполнения.

Интерактивные тренажёры кода: сильны в задачах, но реже совмещают полноценный русскоязычный урок, локальные evidence Attempt и явное разделение «подсказка ≠ сдача».

8. Технологии и инструменты

Next.js (App Router), React, TypeScript, Tailwind CSS.

Monaco Editor и запасной textarea.

Pyodide 0.27.7 в Web Worker.

Vitest и Playwright для учебных и e2e-проверок.

Хранение прогресса: localStorage (без БД и аккаунтов в прототипе).

Опционально (не в публичном демо): Ollama /api/chat на сервере приложения.

9. Текущий статус и результаты

Стадия: ☑ прототип (узкий MVP учебного цикла).

Уже работает и проверено на публичном демо без авторизации:

Сайт https://chgu-ai-academy.vercel.app.

Главная за несколько секунд объясняет проблему и предлагает путь «урок → ошибка → подсказка → исправление → прогресс».

Урок «Переменные и типы данных» открывается; практика загружает Pyodide по HTTPS (runtime-worker.mjs и pyodide.mjs отвечают 200).

Неверное решение (константа вместо вычисления) отклоняется автоматической проверкой.

Кнопка «Помощь по ошибке» показывает режим «подготовленные подсказки» без готового решения первой репликой.

Верное решение принимается; страница прогресса показывает принятую задачу и сохраняет состояние после перезагрузки вкладки.

Мобильный экран 390 px: главная и готовность runtime на практике проверены.

Автотесты среды разработки: npm run typecheck, npm run build, npm run test:learning, npm run test:mentor (включая grading через Pyodide в Node и имитацию ответов Ollama /api/tags и /api/chat). Имитация Ollama не приравнивается к проверке живой модели.

Подготовленный режим помощи — основной в публичной среде.

Локальная модель: серверный адаптер к Ollama предусмотрен для частного запуска; в публичном демо вызовы отключены. Живой ответ модели на публичном сайте не проверялся и не обещается судьям.

Планируется: урок «Условия и логика» и дальнейшие темы, пилот с группой студентов, при необходимости усиление изоляции исполнения.

9.1. Как проходит демонстрационный сценарий

1) Открыть демо. 2) Перейти к уроку и затем к практике «План на учебную неделю». 3) Отправить заведомо неверный код (например, зафиксировать total_hours = 15 без произведения входных значений). 4) Убедиться, что проверка не приняла решение. 5) Открыть подсказку и запросить помощь по ошибке. 6) Исправить код с вычислением total_hours = days * hours_per_day и f-строкой. 7) Пройти проверку. 8) Открыть «Прогресс» и обновить страницу — принятая задача сохраняется. Освоение не повышается от чтения урока, самопроверки или просмотра подсказки.

12. Риски и ограничения

Клиентский Pyodide — учебный прототип, не production-песочница для недоверенного серверного кода.

LocalStorage зависит от браузера; нет кросс-устройств без аккаунта.

Публично используется подготовленный режим помощи, чтобы не зависеть от локальной модели.

Для внедрения нужна организационная поддержка подразделения — подтверждённых соглашений нет.

Приложение C. Архитектура прототипа (кратко)

Клиентский слой отвечает за урок, редактор и отображение результата. Исполнение Python вынесено в отдельный Web Worker с Pyodide, чтобы не блокировать интерфейс и ограничивать время выполнения.

Слой проверки сравнивает stdout и значения переменных после исполнения. Принятие задачи создаёт Attempt; Mastery обновляется только при наличии валидных доказательств успешных тестов.

Слой помощи не выставляет оценку. В публичной среде используется подготовленный ответ с ссылкой на раздел урока. Передача кода на сервер модели возможна только после явного согласия и не включена в публичный сценарий по умолчанию.

Хранилище прогресса локально в браузере с версией схемы и валидацией. Сброс затрагивает только учебный ключ и не трогает тему оформления. Такое разделение позволяет пилотировать методику на небольшой группе студентов без немедленного внедрения серверной песочницы и без заявления о готовой годовой академии.
