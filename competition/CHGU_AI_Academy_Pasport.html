3. Аннотация проекта

CHGU AI Academy создаёт проверяемый учебный цикл «урок → задача → объективная проверка → помощь после ошибки → прогресс». Для студента без регистрации доступны полноценный урок «Переменные и типы данных», две задачи с запуском Python в браузере (Pyodide в Web Worker), сохранение черновика и Attempt/Mastery в локальном хранилище, а также помощь в режиме подготовленных подсказок. Проект адресован студентам начального уровня и методистам, которым нужна честная проверка без подмены «нажал кнопку = сдал». Статус: работающий прототип одного модуля, а не завершённая годовая программа.

4. Проблема и актуальность

Проблема: при самостоятельном изучении программирования студент часто не получает быстрой объективной обратной связи. Чтение теории и самопроверка не подтверждают навык; без запуска кода ошибка остаётся неочевидной; готовые ответы чат-ботов легко выдают решение целиком и не отделяют подготовку от освоения.

С кем встречается: студенты нулевого/начального уровня; преподаватели вводных курсов, которым нужен прозрачный учебный контур до подключения тяжёлой инфраструктуры LMS.

Актуальность подтверждается практикой вводных курсов программирования (ориентиры: открытые программы CS50 Python и аналоги), где цикл «объяснение → задача → проверка» является базовым, а также наличием в Университете конкурса ИТ-проектов как площадки для прикладных образовательных решений. Мы не заявляем официальное партнёрство с Harvard/MIT/fast.ai/Hugging Face.

5. Целевая аудитория и сценарии

Студент ЧГУ / начинающий: проходит урок, сдаёт задачу, видит ошибку тестов, читает подсказку, исправляет, сохраняет прогресс.

Судья/гость демо: без регистрации проходит путь главная → урок → намеренно неверная попытка → подсказка → успешная проверка → /progress.

Методист (перспектива пилота): смотрит, что оценка ставится только тестами, а помощь не меняет Mastery.

6. Цель и задачи

Цель: показать реализуемый прототип адаптивного обучения программированию с объективной проверкой кода в браузере и честной маркировкой режимов помощи.

Реализовать урок и две проверяемые задачи по переменным.

Подключить Pyodide в Worker с ограничениями времени и вывода.

Сохранять Attempt/Mastery локально с валидацией доказательств.

Дать помощь после ошибки без готового решения первой репликой.

Подготовить пилотный контур внедрения на небольшой группе студентов.

7. Решение и новизна

Как работает: серверный рендер урока (Next.js) + клиентская практика с Monaco/простым редактором; выполнение Python только в браузерном Worker; grading по stdout и состоянию переменных; наставник через /api/mentor (в публичной среде — сразу подготовленные подсказки; локальная Ollama опциональна и не обещается публично).

Сравнение с альтернативами по конкретным функциям (без заявления «уникальности»):

Moodle / типовая LMS: сильна в курсах и оценках преподавателя; обычно нет встроенного безопасного Python-рантайма в браузере «из коробки» и нет нашего узкого цикла mastery только по тестам.

Лектории/видеоплатформы (пример класса: Coursera-подобные курсы): дают контент и квизы; слабо закрывают локальный запуск кода студента и адресный разбор конкретной ошибки исполнения без отдельной среды.

Интерактивные тренажёры кода (класс продуктов вроде online Python sandboxes / coding practice): часто сильны в задачах, но реже совмещают полноценный русскоязычный урок, локальное сохранение evidence Attempt и явное разделение «подсказка ≠ сдача».

Отличие прототипа для пилота ЧГУ: узкий проверяемый цикл на русском, открытый клиентский runtime, прозрачные статусы помощи и освоение только по реальным тестам. Это преимущество сценария, а не доказанная рыночная уникальность.

8. Технологии и инструменты

Next.js (App Router) + React + TypeScript + Tailwind CSS.

Monaco Editor (локальная раздача), запасной textarea.

Pyodide 0.27.7 в Web Worker (локальные ассеты после postinstall).

Vitest + Playwright для учебных/наставнических/e2e проверок.

Опционально: Ollama POST /api/chat (серверные настройки; в production по умолчанию отключено ожидание).

Хранение прогресса: localStorage ключ chgu-ai-academy:learning:v1 (без БД и аккаунтов).

9. Текущий статус и результаты

Стадия: ☑ прототип (ближе к узкому MVP учебного цикла). Не идея и не готовый продукт полной академии.

Уже работает (можно проверить в интерфейсе):

Урок «Переменные и типы данных», самопроверка, две задачи.

Запуск/проверка Python в браузере, таймаут 5 с, обрезка вывода 20 КБ.

Сохранение черновика, Attempt, Mastery; «Продолжить обучение»; сброс только учебного ключа.

Помощь в режиме подготовленных подсказок с явной маркировкой.

Проверено автоматическими тестами в среде разработки (фактические прогоны зафиксированы в отчётах tasks/):

npm run typecheck, npm run build — успешно.

npm run test:learning / test:mentor — успешно (включая grading через Pyodide в Node и моки Ollama).

npm run test:e2e — сценарий урок/ошибка/подсказка/успех/прогресс/Worker retry.

Подготовленный режим помощи: основной для публичной среды.

Локальная модель: технически подключена (адаптер Ollama), живой ответ в среде подготовки не проверен (сервис недоступен).

Планируется: расширение уроков, пилот с группой студентов, серверная изоляция кода при росте угроз, опциональный auth.

10. Практическая ценность

Студент получает быстрый цикл обратной связи без установки Python.

Преподаватель/организатор пилота видит, что «сдано» только при прохождении тестов.

Измеримые показатели пилота (предлагаемые): доля завершивших урок; доля успешных задач после ≥1 ошибки; медиана времени до первой успешной попытки; доля оценок «подсказка помогла» в коротком опросе.

11. План реализации

Сейчас–ноябрь 2026: заочный конкурсный пакет, публичное демо, фиксация ограничений.

Декабрь 2026 – февраль 2027: пилот 15–30 студентов вводного уровня (при согласии подразделения; договорённости пока не оформлены).

Далее: 2–3 дополнительных урока Python, журнал событий для методики, при необходимости серверный runner.

Ресурсы пилота (предварительно, без вымышленных смет): 1–2 разработчика-студента, куратор методики, доступ к аудитории/часу консультаций, хостинг статического/Next-приложения.

12. Риски и ограничения

Клиентский Pyodide не является production-песочницей для недоверенного серверного кода; тесты видимы в браузере.

LocalStorage зависит от браузера пользователя; нет кросс-устройств без аккаунта.

LLM-наставник может нарушать педагогические правила — поэтому публично используется подготовленный режим.

Риск внедрения: нужна организационная поддержка кафедры/института — на момент паспорта подтверждённых соглашений нет.

Снижение: честные статусы, узкий пилот, метрики, отказ от завышенных обещаний «готовой академии».

15. Целевые клиенты / пользователи и рынок

Первичные пользователи: студенты вводных курсов программирования Университета и аналогичных программ. Вторичные: преподаватели/ассистенты, которым нужен прозрачный контур практики до полноценной LMS. 16. Модель коммерциализации или устойчивого внедрения

На текущей стадии приоритет — устойчивое внедрение в образовательный процесс, а не выручка. Реалистичный путь: согласование пилота с профильным институтом/курсом; использование как открытого учебного прототипа; при развитии — внутренний университетский сервис или модуль к существующей LMS. Коммерческие варианты (подписка для школ/курсов, сопровождение внедрения) возможны позже и не заявлены как текущий доход. Партнёрство с Университетом как юридический факт на момент подачи не утверждается — только намерение предложить пилот.

17. Экономика и план выхода на рынок / внедрения

Предварительные ресурсы пилота (оценка порядка, не смета договора): труд команды (студпроект), бесплатный/хобби-хостинг фронтенда, время куратора на 2–4 недели наблюдений, опросник обратной связи. Денежная выручка и число пользователей не вымышляются. Канал: аудиторные занятия / консультации / ссылка на демо. Измеримый эффект вместо выручки: рост доли успешно решённых задач после ошибки и завершение урока в отведённое время. Этапы: демо конкурса → пилот малой группы → решение о расширении контента.
